## 1. ВЫЯВЛЕНИЕ ПРИЧИНЫ ДЕГРАДАЦИИ ИНФЕРЕНСА YOLO26N

### Физическая и математическая природа ошибки

В коммите `7c5df4a` в модуль [calibration.py](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/engine/calibration.py) было внесено искусственное ограничение на наклон регрессионной прямой:
```python
# ОШИБОЧНЫЙ КОД:
geo_by = self.user_distance_mm * (math.pi / 180.0) * px_per_mm_y  # +99.208 px/deg
if wy[1] <= 0.15 * geo_by:
    wy[1] = geo_by  # Насильственная перезапись положительным числом +99.208
```

#### Математический анализ координатных систем:
1. **Экранная система координат (Screen Coordinates):**
   * Начало $(0, 0)$ находится в **левом верхнем углу**.
   * Ось $Y$ направлена **сверху вниз** ($Y_{top} \approx 0$, $Y_{bottom} \approx 1800$ px).
2. **Угловая система координат взгляда (Spherical Elevation / Pitch):**
   * Угол наклона взгляда вверх (Elevation) по стандартной физической конвенции **положителен** ($\theta > 0$).
   * Угол наклона взгляда вниз по стандартной физической конвенции **отрицателен** ($\theta < 0$).
3. **Физическая связь экрана и угла Pitch:**
   $$\Delta Y_{screen} = -D \cdot \tan(\theta) \cdot \frac{H_{px}}{H_{mm}}$$
   * При взгляде вверх ($\theta > 0$): точка на экране смещается вверх, то есть $Y$ **уменьшается** ($\Delta Y < 0$).
   * При взгляде вниз ($\theta < 0$): точка на экране смещается вниз, то есть $Y$ **увеличивается** ($\Delta Y > 0$).
   * Следовательно, частная производная и наклон регрессии строго **отрицательны**:
     $$\frac{\partial Y_{screen}}{\partial \theta} = - \text{geo\_by} \approx -99.208 \text{ px/deg}$$

#### Механизм деградации:
Фактический наклон модели YOLO26n по выборке калибровки пользователя равен:
$$w_y[\text{pitch}] = -121.38 \text{ px/deg}$$
Условие `-121.38 <= 0.15 * 99.208` (+14.88) оказалось истинным. Алгоритм стер физический отрицательный наклон $-121.38$ и перезаписал его на $+99.208$.
В результате калибровка была **перевернута по вертикали на 180°**:
* Когда пользователь смотрел вниз (pitch $< 0$), калиброванная точка $Y_{pred}$ улетала вверх.
* Когда пользователь смотрел вверх (pitch $> 0$), точка $Y_{pred}$ улетала вниз.
* Это вызвало отрицательную корреляцию $R_y = -0.898$ на динамическом тесте и надуло угловую ошибку с **2.98°** до **7.09°**.

## 4. СПЕЦИФИКАЦИЯ АРХИТЕКТУРНЫХ АДАПТЕРОВ (`mvp/adapters/`)

Каждая модель вынесена в изолированный адаптер, наследующий интерфейс [`BaseGazeAdapter`](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/adapters/base.py):

### 1. [L2CSAdapter](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/adapters/l2cs_adapter.py)
* **Архитектура:** ResNet-50 + двойная классификационная голова по 90 бинов с шагом 4° ([-180°, +180°]).
* **Входной тензор:** 224x224 RGB, нормализация ImageNet (`mean=[0.485, 0.456, 0.406]`, `std=[0.229, 0.224, 0.225]`).
* **Декодирование голов:** `fc_yaw_gaze` $\to$ Yaw, `fc_pitch_gaze` $\to$ Pitch.
* **3D вектор:** $g_x = -\sin(\text{yaw})\cos(\text{pitch})$, $g_y = -\sin(\text{pitch})$, $g_z = -\cos(\text{yaw})\cos(\text{pitch})$.

### 2. [GazeTRAdapter](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/adapters/gazetr_adapter.py)
* **Архитектура:** ResNet-18 backbone + 6-слойный Transformer Encoder с 50 позиционными эмбеддингами.
* **Входной тензор:** 224x224 **BGR** (прямой кроп OpenCV), диапазон значений **$[0, 1]$** (БЕЗ вычитания ImageNet mean/std!).
* **Декодирование выхода:** `angles[:, 0]` $\to$ Yaw (азимут), `angles[:, 1]` $\to$ Pitch (элевация) в радианах.

### 3. [PureGazeAdapter](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/adapters/puregaze_adapter.py)
* **Архитектура:** ResNet-50 backbone + регрессионная голова `ResGazeEs` (`Linear(2048, 2)`).
* **Входной тензор:** 224x224 **BGR**, диапазон значений **$[0, 1]$** (`to_tensor`).
* **Декодирование выхода:** `angles[:, 0]` $\to$ Pitch (элевация), `angles[:, 1]` $\to$ Yaw (азимут) в радианах.

### 4. [IdiapResNet18Adapter](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/adapters/idiap_adapter.py)
* **Архитектура:** Dual-Stream ResNet-18 (Head Stream 512 + Left Eye 512 + Right Eye 512) $\to$ `Linear(1536, 512)` $\to$ `Linear(512, 3)`.
* **Входной тензор:** Три кропа по 224x224 RGB, нормализация ImageNet.
* **Декодирование выхода:** 3D вектор $(g_x, g_y, g_z) \to \text{pitch} = \arcsin(-g_y)$, $\text{yaw} = \arctan2(-g_x, -g_z)$.

### 5. [YOLOAdapter](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/adapters/yolo_adapter.py)
* **Архитектура:** Backbone YOLO26n + FPN + Spatial Soft-Argmax + Head/Gaze Heads.
* **Входной тензор:** 224x224 RGB, нормализация ImageNet.
* **Декодирование выхода:** Векторы и углы взгляда и позы головы напрямую из словаря выходов сети.

### 6. [MediaPipeAdapter](file:///c:/Users/jack_/MAIN/ВУЗ/ВКР/mvp/adapters/mediapipe_adapter.py)
* **Архитектура:** MediaPipe Vision FaceLandmarker (FaceMesh 478 точек + Blendshapes + 4x4 матрица позы).
* **Признаки:** Нормированные смещения радужки $(ix, iy)$, разности блендшейпов, поворот головы по Rodrigues.
